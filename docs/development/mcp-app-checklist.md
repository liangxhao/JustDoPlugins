# MCP App 插件接入与验收清单

用于需要交互界面的 OpenClaw 扩展。实现步骤及元数据示例见[MCP App 开发与宿主接入](mcp-app-development.md)。普通插件无需完成本清单。

所有 MCP App 完成“必需项”；按需项只验收插件实际声明的能力。以下复选框是待核对事项，不表示当前两个插件已经全部通过。身份和来源即使由标准 AppBridge 承接，也须验证插件接口的实际权限边界。

验收记录填写插件 ID、版本、源代码提交、目标宿主与 OpenClaw 版本、交付包哈希及实际结果。未选择的能力标为“不适用”，不应为完成清单而增加功能。

## 必需项

### 扩展和服务

- [ ] 扩展位于 `plugins/extensions/<name>/`，在 `package.json` 注册 `mcpApp.contractVersion: 1`，提供 `app.ts` 与 `server.ts`；新增 App 自动进入扩展的构建、规范测试和打包列表。
- [ ] 清单与扩展入口的 ID 一致；MCP 服务名、工具引用、资源 URI 和交付路径逐项对应且稳定，不要求它们同名，也不依赖开发机或下游源码目录。
- [ ] 完整目录或压缩包可独立导入；启用后服务可发现，停用后相关服务和入口撤下。
- [ ] 当前宿主支持并开启 MCP Apps，工具策略允许；MCP 服务没有被同名覆盖配置替换。
- [ ] 工具参数经过 schema 校验，写入行为如实声明，stdio 标准输出不混入日志。

### 身份和来源

- [ ] 界面由真实工具结果或原生启动流程准入，未从助手正文、标题或 App 自报 JSON 授予权限。
- [ ] 服务、工具、UI 资源、工具调用和原生视图对应；viewId 本身不被当作访问凭据。
- [ ] 绑定真实会话、会话实例、助手和当前认证连接；旧连接或另一会话不能复用原交互权限。
- [ ] 插件根据真实工具执行、手动启动或文件打开的认证来源处理请求，不根据界面位置、标题或同名应用推断身份。
- [ ] 切换会话、断线、权限变化及关闭后，旧回调不能写入新实例或恢复旧权限。
- [ ] 标准 App 复用宿主认证和 AppBridge，HTML 不携带宿主凭据，不另建绕过授权的连接。

### 界面和资源

- [ ] UI 工具声明 `_meta.ui.resourceUri`，对应 `ui://` 可读，返回 URI 与 `text/html;profile=mcp-app` MIME 正确。
- [ ] App 按标准协议初始化、接收工具结果并实际显示；不把普通 HTML/SVG 文本当作 MCP App。
- [ ] 成功结果与失败结果分开，先核对 RPC 成功状态再解析 payload；错误在界面中可理解，不伪报成功。
- [ ] JS、CSS、字体、Worker、WASM 等所需资源随包可用，干净缓存和禁止公网时仍可加载。
- [ ] CSP、消息来源和沙箱边界保持有效；额外 frame relay 只接受确切父子窗口。
- [ ] 若使用 loopback 服务，限制监听地址、Host、路径与方法，并避开 Chromium 禁用端口。

### 单行共享标题栏（本仓库 App 必需）

这是本仓库的 App 规范；协议层仍为协商扩展，不要求外部普通 App 或所有宿主默认实现。

- [ ] 已实际实现布局处理后，再声明 `experimental['ui/shared-header'] = { version: 1 }`；不将其宣称为标准 MCP Apps 或所有宿主的默认能力。
- [ ] 连接后及现有 host context 回调中，检查宿主版本并校验同名 `{ height, left, right }`；不覆盖已有主题、尺寸和模式处理。
- [ ] 仅顶部工具栏隐藏重复标题并按尺寸避让；画布保持正常宽度，必要状态与按钮可见、可访问且未被遮挡。可编辑标题隐藏后仍可重命名。
- [ ] 无能力、缺失、`null`、错误版本或无效尺寸时，恢复完整独立标题栏和默认内边距，不残留旧布局。
- [ ] 重复、撤回及重新启用布局均保留同一编辑器、未提交输入和撤销／筛选状态；创建、保存和导出调用计数不因布局通知增加。
- [ ] 按钮仍在原 iframe 内执行既有业务流程；没有以展示字段改写来源、会话、权限或成功状态，也不依赖宿主内部界面结构。
- [ ] 提供本仓库约定的三个 DOM 测试标记及共享状态属性；重新构建后 `npm run test:apps` 通过真实初始化、布局和回退检查，不能只修改能力声明或使用陈旧构建产物。

## 按需项

### 手动启动入口

- [ ] 工具在 `_meta['openai/ui'].entrypoints` 按公开协议声明 `thread` 或 `global` 范围，并能用空参数启动。
- [ ] 声明适当 App 可见性，真实 MCP 发现结果保留工具元数据；服务返回可由同一 UI 消费的结果。
- [ ] 不按入口展示位置改变对象归属或重新执行创建工具；未知启动不自动重放。

### 图标

- [ ] 图标放在工具或服务顶层 `icons`，构建后仍可从真实 MCP 目录取得。
- [ ] 使用体积受控且可解码的内嵌图片，满足协议约束，无公网或本机文件 URL，提供需要的主题版本。

### 展示环境与本地状态

- [ ] 使用标准 host context 处理尺寸、主题和模式，重复通知保持幂等，不根据界面位置增加业务协议。
- [ ] 环境通知不重建编辑器、重读初始内容或重新执行创建工具；保留未提交输入和插件承诺的撤销／筛选状态。
- [ ] 业务内容更新核对对象 ID 与内容代次，保护并行手改，旧异步结果不覆盖新编辑。
- [ ] 按标准关闭通知清理自身资源，遵守当前会话与能力约束，不尝试恢复已失效权限。

### 内容关联与稳定回执（按需）

- [ ] 与宿主明确受审查的可选适配；不把插件自有字段、记录类型或长度上限宣称为标准 SDK 能力。
- [ ] 业务内容 ID、原视图关联和恢复 viewId 分开；服务／资源／原生会话来源从真实准入核实，正文自报不能授予权限。
- [ ] 仅实际应用 ACK 产生“界面已更新”回执，失败、冲突、未知及迟到结果不误报；工具调用与已有原生 run 身份精确匹配。
- [ ] 从真实 Gateway 历史响应验证紧凑回执，不只测含完整 details 的模拟数据；实时结果与历史结果中的业务目标及确认状态一致。
- [ ] 记录有明确类型／版本和长度上限，不复制大业务正文或临时授权；伪造助手文本、其他工具及错调用／错 run 不被解析为有效业务回执或用于授予权限。

### 文件预览和保存

- [ ] 声明 `file` 入口和支持扩展名，仅处理原生签发的合法文件资源与声明支持的类型。
- [ ] 校验工作区、文件类型、大小和资源生命周期；文件名或路径不充当授权。
- [ ] 明确打开文件、保存业务文档、覆盖源文件、另存为和导出的区别。
- [ ] 源文件写回使用当前视图权限和写入审批，校验 ETag 或等价冲突依据；授权失效、外部修改、取消和未知结果均不盲目重写。

### 自定义原生接口

- [ ] 使用匹配版本的公开 SDK、所需 manifest contracts 和认证请求；不将入参会话 ID 或 admin scope 当作目标归属证明。
- [ ] 重读原生会话实例、生命周期、当前工作目录与 MCP 扩展归属；同名服务覆盖和目录变化使旧准备失效。
- [ ] 操作视图时核验宿主已准入的来源身份；需要额外来源证明时使用确切视图原连接，不从静态目录或其他实例借证明。
- [ ] 在异步准备和敏感操作边界重验请求、连接及授权；旧 token、跨视图请求和迟到回执被拒绝。

### 上下文和连续修改

- [ ] 检查宿主能力后同步有界内容，明确上下文同步不等于文件保存、不自动触发回复。
- [ ] 若承诺发送包含未保存编辑，实现宿主支持的准备约定，提交当前输入并等待同步；失败保留草稿与画布。
- [ ] 稳定业务 ID 区分同名对象，精确目标绑定到发送时实例；歧义时询问，不按标题或最后消息猜测。
- [ ] 继续修改复用原实例，检查内容代次和并行手改，收到实际应用回执后才报告界面更新成功。
- [ ] 验证撤销和切换返回；不因界面搬动、重读初始结果或重新执行创建工具丢失编辑。

### 持久化和恢复

- [ ] 说明持久文档、原生已确认结果及未保存草稿各自的恢复范围；存储身份不替代当前会话授权。
- [ ] 重启按可靠记录创建当前视图，不重放业务工具、不复活旧授权或未知候选，不承诺未实现的历史版本功能。
- [ ] 同内容多回执并发恢复不会重复创建业务对象；保留原内容来源，不升级旧权限。
- [ ] 只读恢复不注册旧编辑目标；手动／文件来源恢复有自身证据，不假设存在聊天创建工具记录。

## 交付验收

- [ ] 源码变化后按顺序完成类型检查、构建、相关自动测试及所选能力的浏览器验证；命令见[测试与验收](testing.md)。
- [ ] 重新打包并核对最终安装目录和包哈希，包含原生入口、全部运行资源和第三方许可，无开发依赖或首次启动下载。
- [ ] 在匹配版本的真实宿主验收所选入口、会话身份、来源隔离和资源权限；独立测试页面不代替该项。
- [ ] 对所选能力覆盖失败、取消、断线、切换、关闭后迟到结果及重启；发送、启动和写入未知时不自动重放。
- [ ] 插件详细说明写清支持能力、容量和限制，开发导航与插件列表同步；验证记录不包含用户凭据或真实聊天内容。

纯文档修改只需检查内容、相对链接及 `git diff --check`；不将整套运行验收作为修改指南文字的前置条件。
