# 测试与验收

所有命令从仓库根目录执行。以下流程验证当前 `plugins/extensions/` 中的扩展；其余类型的测试要求随实际插件补充。先按[开发指南](README.md)准备依赖与 SDK，修改源码后重新构建。

MCP App 发布使用[接入 checklist](mcp-app-checklist.md)记录必需项和所选能力。认证来源、入口元数据和资源权限在匹配的 OpenClaw 环境中验收；没有选择的文件、连续编辑或恢复能力不作为发布门槛。

## 自动验证

```sh
npm run check
npm run build
npm test
npm run test:ui
npm run pack:apps
```

| 命令                | 验证范围                                                                                                           |
| ------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `npm run check`     | App 注册完整性及插件、共享实现、测试宿主的类型检查，使用匹配版本的公开 SDK                                         |
| `npm run build`     | 浏览器资源、stdio 服务、原生入口、完整性清单与第三方许可                                                           |
| `npm test`          | 注册 App 的浏览器规范检查，以及内容戳、准备确认、重复拒绝、端口、数据校验、CSV、XLSX、文件授权、MCP 服务和文档并发 |
| `npm run test:apps` | 单独检查自动发现的全部 App：真实握手、共享标题栏、窄宽度、独立回退及反例拒绝                                       |
| `npm run test:ui`   | 真实编辑器的保存、导出、重载、文件预览、源文件冲突、当前内容接口、一次撤销及真实聚合查询                           |
| `npm run pack:apps` | 先通过 App 规范检查，再制作独立导入目录与压缩包，计算交付包哈希                                                    |

测试和打包依赖已构建产物；App 检查会比较源码指纹和产物哈希，拒绝源码变化后未重新构建的结果。
`npm test`、`npm run test:apps` 和 `npm run pack:apps` 均需已安装 Chrome；测试不会自动下载浏览器，缺失时直接失败，不跳过规范检查。
单独排查时可运行 `node --test tests/xlsx-writeback.test.mjs`，或用 `npm run test:ui -- univer-write` 验证指定浏览器场景。
浏览器模式还包括 `univer`、`perspective`、`univer-file` 和 `perspective-file`。

`node tests/univer-offline.mjs` 验证增强后的 Univer：普通文档、减少动画、授权源文件三种场景。可单独传 `document`、`reduce` 或 `source`。覆盖真实中英文资源、agent 样式/工作表/行列/范围操作、一次撤销重做、原生键盘填充与共享公式、跨表引用、手改冲突、保存重开和四种下载格式；源文件场景核对值及格式写回、原件未知部件保留，以及结构/规则改动在写入前拒绝。报告和截图输出到 `test-results/ui/univer-offline/`，测试使用合成数据并拒绝公网请求。

`tests/univer-operations.test.mjs` 使用隔离的真实无界面引擎验证与界面共用的命令、公式引用和共享公式物化，另覆盖队列容量、取消、关闭、Worker 监听清理及真实 stdio 并发 revision。`tests/univer-features.test.mjs` 覆盖原生规则空态归一化、不可保留的 XLSX 功能明确拒绝及大表文本导出的边界扫描。

`tests/univer-offline-data-review.test.mjs` 验证行列元数据不能越过声明容量，以及只有隐藏/尺寸属性的空行空列在 XLSX 导入时的边界；`tests/xlsx.test.mjs` 同时检查这些空行导出、重新导入和原数据不变。

`node tests/app-usability.mjs` 验证两个 App 的人机协作流程，包含中文/普通动画与英文/减少动画的四个场景（可传 `univer-zh`、`univer-en`、`perspective-zh`、`perspective-en`）：空库首页、真实选择文件导入、Agent 创建/修改/保存、人手改后继续修改、过期保存拒绝、保存重开，以及延迟上下文确认时的串行发送和首页目标清理。使用真实键盘输入核对 Perspective 原生整数编辑，非法值必须在写入前拒绝。报告和截图位于 `test-results/ui/app-usability/`。

`tests/perspective-native-edit.test.mjs` 覆盖手工输入的完整数值与既有类型规则、捕获校验先于原生写入、监听幂等和销毁，以及接近 2 MiB 的完整分析 JSON 往返。共享状态测试还覆盖已保存但副本打开失败、已确认保存后的快照读取失败，以及旧描述晚于显式 prepare 返回时不得覆盖新选区。

需要重现 Perspective 的完整非地图图集时，在最新构建后运行：

```sh
node tests/perspective-gallery.mjs
```

仅排查一个样例时可传 fixture ID，例如 `node tests/perspective-gallery.mjs density`。样例定义在 `tests/fixtures/perspective-gallery.mjs`，全部为确定性的合成演示数据。完整运行覆盖 Datagrid 与 13 个非地图图表：真实 MCP 创建、界面保存、重开后的当前查询、导出前屏幕绘图区像素、原生导出及 App CSV 下载；截图、原生图像、可导入 JSON、结果 CSV、报告和 HTML 图集保存在 `test-results/ui/perspective-gallery/`，不提交 Git。

图集检查绘图区而非仅检查图例、插件名称或原生导出；后者可能触发上游重绘，不能证明首次显示正常。它同时拒绝浏览器错误与公网请求。三种地图因缺少离线底图明确排除，14 个展示器覆盖不等于上游全部功能接入。普通五模式验证仍保留原职责，图集按图表或生命周期变更另行运行。

`node tests/perspective-offline.mjs` 从真实 MCP 导入合成 NDJSON 与显式日期/整数类型，运行普通和减少动画两种浏览器设置，覆盖多面板 agent 创建、真实单元格点击联动、手动面板管理、旧内容戳冲突、保存重开及空面板恢复；普通模式还检查各类 App 下载并真实解码 Arrow/PNG。报告与截图输出到 `test-results/ui/perspective-offline/`。PNG 导出必须保留主视图的联动过滤，不能仅验证图片字节。

`tests/live-app.test.mjs` 验证内容戳、当前实例、同步失败、同步中手改、重复和未知操作、关闭以及摘要上限。`tests/live-app-checks.mjs` 通过真实 AppBridge 发现并调用 App 工具，验证未保存状态、输入提交、当前编辑器保留、Univer 稀疏修改与一次撤销，以及 Perspective 实际过滤聚合结果；同时核对文档库及业务调用计数没有被这些操作改变。`perspective-file` 覆盖 TSV 只读来源、分析配置及保存副本，`tests/loopback.test.mjs` 验证实际禁止端口释放、重新绑定和重试上限。
`tests/ui-state.test.mjs` 使用真实共享界面逻辑，覆盖保存期间已提交或尚未提交的输入、画布锁定、通知忙状态交接和导航等待。服务测试从复制到临时目录的独立产物运行，验证真实引擎拒绝无效表达式/筛选/聚合、失败后继续处理合法请求、校验后并发 revision 冲突，以及长文本分页的 UTF-8 上限和配置省略。
服务回归还覆盖取消创建/保存不落库、有效与无效图表样式、显式列类型及全空数值列。真实分析界面通过与 Datagrid 相同的公开表更新接口验证数据编辑标脏、源数据保存、全空列类型保持和重新打开，使用实际插件规范校验样式。

App 注册和发现统一位于 `scripts/apps.mjs`，仅扫描 `plugins/extensions/`。新增 `plugins/extensions/<name>/app.ts` 却没有注册 `mcpApp.contractVersion: 1`，或注册后缺少入口，检查直接失败；普通扩展不加入此列表。`tests/app-registration.test.mjs` 同时验证 skills、mcp-servers、hooks 不进入扩展 App 流程。测试从每个真实 MCP 服务列出并读取全部 App UI 资源，不维护另一份 App 名单。

`tests/app-contract-checks.mjs` 的同一组断言同时用于构建界面和四个故意不合规的 App，验证漏声明、只声明不处理、撤回不恢复及压缩画布都会被拒绝。通用检查证明实际能力声明、工具栏几何、按钮可访问、原 DOM 和未提交标题保留，以及布局通知不调用业务工具；编辑器内部撤销、选区、筛选和原生授权仍需专用测试与集成验收。

## 测试边界与宿主验收

服务测试使用真实 stdio MCP 子进程，覆盖声明、资源、持久化和跨进程冲突。
界面测试使用标准 AppBridge 和本机 Chrome，拒绝所有公网请求，检查真实编辑器、保存、导出和重新加载。
浏览器截图与验证记录输出到仓库 `test-results/ui/`；
它验证独立应用，不能代替产品内真实模型端到端验收。

宿主集成验收由宿主工程维护。插件发布时还需在匹配版本的宿主中验证目录/压缩包离线导入、
扩展启停、模型调用、文件资源读取、源文件保存与权限边界；独立 AppBridge 测试不能替代这项验收。
本仓库不要求宿主源码位于某个固定目录，宿主普通构建和测试也不依赖本仓库。

验收时核对以下操作是否符合插件的详细说明：

- 干净环境中离线导入目录或压缩包，启用、停用和卸载扩展。
- 发现 MCP 服务、打开手动入口、通过模型创建和重新打开文档。
- Univer 的文件预览、源文件保存、备份、外部修改冲突与授权失效。
- Perspective 的数据导入、分组筛选、视图保存与 CSV 导出。

### 接口与状态的验证方法

以下场景按插件实际声明的能力验收，不为完成清单而引入内容回执协议、版本数据库或模型编辑工具。界面放置、标签、焦点和窗口组织属于宿主工程的测试范围。

| 场景                          | 插件验证内容                                                                                                                                                                                      |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 尺寸、主题与模式变化          | 通过标准 host context 通知，插件只更新必要样式与布局；保留未提交输入、选择和承诺的撤销／筛选状态，业务调用计数不增加                                                                              |
| 共享标题栏（本仓库 App 必需） | 双方支持 `ui/shared-header` v1 时，按有效尺寸仅调整顶部工具栏；独立布局、启用、重复通知、撤回、再次启用和无效值均覆盖，必要提示与按钮可访问，编辑器和业务调用计数保持不变；不支持的宿主仍完整回退 |
| 重复结果与等价通知            | 处理幂等，无重复初始化或更新循环；真实内容更新核对对象与代次，不覆盖并行编辑                                                                                                                      |
| 同名对象与来源隔离            | 不按标题或显示位置定位内容；跨服务／资源／原生会话的调用不能借用另一实例的权限                                                                                                                    |
| 可选的历史回执                | 使用实际 Gateway 投影后的响应，实时与历史中的目标、调用及确认状态一致；错角色／工具／调用／run、失败与未知状态不产生成功回执                                                                      |
| 自定义认证接口                | 旧 token、旧请求和迟到回包不能在会话、连接或权限变化后恢复操作；未知发送与写入不重放                                                                                                              |
| 持久化与恢复                  | 按已保存／已确认范围恢复；同内容并发读取不重复创建业务对象，不复活旧工具授权，也不假定一定有模型创建记录                                                                                          |

独立 `tests/host.ts` 验证标准 AppBridge 与插件界面，不模拟原生认证与历史投影。
需要相关能力时，在匹配版本的 OpenClaw 环境验证这些接口；不把独立页面通过报告为完整集成通过。
当前编辑状态的保留与重启后的持久内容恢复分别记录，截图相似不能证明未提交输入或撤销状态保留。

验证使用隔离状态目录、端口和合成数据，不读取真实用户历史或启动用户的 Gateway。
字段被原生历史过滤时，修复对应结果契约并用真实响应重验，不在 mock 中强行保留字段。
异常断言先在同一基础提交和环境中复现，区分本次回归与既有失败；报告列出通过、失败与未覆盖范围。
源码或测试改变后重新运行受影响验证，保留最终构建／包的身份。

## 报告与产物

`test-results/ui/` 保存浏览器截图、测试工作簿和验证记录，不纳入 Git。
当前扩展的可交付产物位于 `dist/plugins/extensions/` 与 `dist/archives/extensions/`；结构和离线准备要求见[离线构建与交付](offline-delivery.md)。
