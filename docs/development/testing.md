# 测试与验收

所有命令从仓库根目录执行。先按[开发指南](README.md)准备依赖与 SDK，修改源码后重新构建。

MCP App 发布使用[接入 checklist](mcp-app-checklist.md)记录必需项和所选能力。认证来源、入口元数据和资源权限在匹配的 OpenClaw 环境中验收；没有选择的文件、连续编辑或恢复能力不作为发布门槛。

## 自动验证

```sh
npm run check
npm run build
npm test
npm run test:ui
npm run pack:apps
```

| 命令                | 验证范围                                                            |
| ------------------- | ------------------------------------------------------------------- |
| `npm run check`     | 插件、共享实现及测试宿主的类型检查，使用匹配版本的公开 SDK          |
| `npm run build`     | 浏览器资源、stdio 服务、原生入口、完整性清单与第三方许可            |
| `npm test`          | CSV、XLSX、源文件写回、文件授权、缓存、MCP 服务、文档并发及依赖通知 |
| `npm run test:ui`   | 真实编辑器的保存、导出、重载、文件预览和源文件冲突场景              |
| `npm run pack:apps` | 将已构建插件制作成独立导入目录与压缩包，计算交付包哈希              |

测试和打包依赖已构建产物；修改源码后不要直接使用上一次构建的结果。
单独排查时可运行 `node --test tests/xlsx-writeback.test.mjs`，或用 `npm run test:ui -- univer-write` 验证指定浏览器场景。
浏览器模式还包括 `univer`、`perspective` 和 `univer-file`。

## 测试边界与宿主验收

服务测试使用真实 stdio MCP 子进程，覆盖声明、资源、持久化和跨进程冲突。
界面测试使用标准 AppBridge 和本机 Chrome，拒绝所有公网请求，检查真实编辑器、保存、导出和重新加载。
浏览器截图与验证记录输出到仓库 `test-results/ui/`；
它验证独立应用，不能代替产品内真实模型端到端验收。

宿主集成验收由宿主工程维护。插件发布时还需在匹配版本的宿主中验证目录/压缩包离线导入、
扩展启停、模型调用、文件资源读取、源文件保存与权限边界；独立 AppBridge 测试不能替代这项验收。
本仓库不要求宿主源码位于某个固定目录，宿主普通构建和测试也不依赖本仓库。

验收时核对以下操作是否符合插件的详细说明：

- 干净环境中离线导入目录或压缩包，启用、停用和卸载扩展。
- 发现 MCP 服务、打开手动入口、通过模型创建和重新打开文档。
- Univer 的文件预览、源文件保存、备份、外部修改冲突与授权失效。
- Perspective 的数据导入、分组筛选、视图保存与 CSV 导出。

### 接口与状态的验证方法

以下场景按插件实际声明的能力验收，不为完成清单而引入内容回执协议、版本数据库或模型编辑工具。界面放置、标签、焦点和窗口组织属于宿主工程的测试范围。

| 场景 | 插件验证内容 |
| ---- | ------------ |
| 尺寸、主题与模式变化 | 通过标准 host context 通知，插件只更新必要样式与布局；保留未提交输入、选择和承诺的撤销／筛选状态，业务调用计数不增加 |
| 重复结果与等价通知 | 处理幂等，无重复初始化或更新循环；真实内容更新核对对象与代次，不覆盖并行编辑 |
| 同名对象与来源隔离 | 不按标题或显示位置定位内容；跨服务／资源／原生会话的调用不能借用另一实例的权限 |
| 可选的历史回执 | 使用实际 Gateway 投影后的响应，实时与历史中的目标、调用及确认状态一致；错角色／工具／调用／run、失败与未知状态不产生成功回执 |
| 自定义认证接口 | 旧 token、旧请求和迟到回包不能在会话、连接或权限变化后恢复操作；未知发送与写入不重放 |
| 持久化与恢复 | 按已保存／已确认范围恢复；同内容并发读取不重复创建业务对象，不复活旧工具授权，也不假定一定有模型创建记录 |

独立 `tests/host.ts` 验证标准 AppBridge 与插件界面，不模拟原生认证与历史投影。
需要相关能力时，在匹配版本的 OpenClaw 环境验证这些接口；不把独立页面通过报告为完整集成通过。
当前编辑状态的保留与重启后的持久内容恢复分别记录，截图相似不能证明未提交输入或撤销状态保留。

验证使用隔离状态目录、端口和合成数据，不读取真实用户历史或启动用户的 Gateway。
字段被原生历史过滤时，修复对应结果契约并用真实响应重验，不在 mock 中强行保留字段。
异常断言先在同一基础提交和环境中复现，区分本次回归与既有失败；报告列出通过、失败与未覆盖范围。
源码或测试改变后重新运行受影响验证，保留最终构建／包的身份。

## 报告与产物

`test-results/ui/` 保存浏览器截图、测试工作簿和验证记录，不纳入 Git。
`dist/plugins/` 与 `dist/archives/` 保存可交付产物；结构和离线准备要求见[离线构建与交付](offline-delivery.md)。
