# 安装与使用

本文介绍两个扩展共用的安装和文档操作流程。插件特有的功能、格式、工具和容量限制见[当前插件列表](../plugins/README.md)中的详细文档。

## 安装准备

使用支持相应原生扩展、MCP 服务和 MCP Apps 能力的 OpenClaw 宿主。开发时匹配的公开 SDK 版本为 2026.10.4；原生菜单和侧栏入口由接入方提供，具体界面可能不同。

从交付方取得单个插件的完整目录或 `.tgz`，不要导入整个开发仓库或只有源码的目录。自行生成交付包时，先按[离线构建与交付](../development/offline-delivery.md)完成准备和验证。

## 导入与启用

1. 在宿主的扩展导入入口选择对应插件的独立目录或压缩包。
2. 按宿主的审查流程完成导入并启用父扩展。
3. 确认扩展声明的 MCP 服务已发现，再从应用入口或模型创建工具打开。

如果宿主提供“插件 → 扩展 → 导入扩展”菜单，可选择生成的 `dist/plugins/univer/`、`dist/plugins/perspective/` 或 `dist/archives/` 下对应的压缩包。以上路径均以仓库根目录为基准。

插件随包包含静态资源与服务代码。运行使用宿主的 Node 24，不需要手工安装依赖、设置 API Key 或下载浏览器资源；附带的 MCP 服务由 OpenClaw 自动管理。
已经导入原生扩展时，不要重复手工配置同名 MCP 服务，以免覆盖原生服务。

## 打开与保存

提供“+ → 应用”菜单的宿主中，可选择插件进入本地文档库，新建、导入或重新打开文档。模型也可以通过各插件的创建工具打开应用。

普通文档的修改需主动点击“保存”，导出操作则通过宿主文件保存接口写入用户选择的位置。Univer 直接打开工作区文件时，“保存”写回该源文件，具体备份和冲突规则以 Univer 文档为准。

本地文档跨会话保留，不是当前对话的消息列表。旧版本保存会被拒绝；遇到冲突，先复制或导出未保存内容，再重新读取。当前不自动合并或后台自动保存。

## 停用、卸载与数据

停用或卸载父扩展会撤下 MCP 服务和应用入口，用户文档保留。默认数据位于用户目录下的 `.local-mcp-apps/<name>/documents.sqlite`，也可通过 `MCP_APP_DATA_DIR` 指定数据目录。

备份数据前先停用服务，再复制整个数据目录，包括 SQLite WAL。各插件的具体数据位置和源文件备份规则见对应详细文档。

## 常见问题

| 现象                                | 检查方式                                                                       |
| ----------------------------------- | ------------------------------------------------------------------------------ |
| 找不到应用入口                      | 检查父扩展是否启用、MCP 是否发现、宿主是否支持相应入口及是否配置了同名覆盖服务 |
| 保存发生版本冲突                    | 保留或导出当前修改后重新读取，不反复提交旧 revision                            |
| 文件授权过期或权限改变              | 按插件提示关闭标签并重新打开文件，重新取得当前授权                             |
| 格式或文件大小不支持                | 核对插件详细文档中的实际能力与容量上限                                         |
| 普通 MCP 客户端没有原生文件预览入口 | 该入口需要宿主的原生扩展适配，不能仅靠手动添加 stdio 服务获得                  |

## 开发时单独调试 MCP

从仓库根目录构建后，可在终端启动单个服务：

```sh
node plugins/univer/dist/server.cjs
node plugins/perspective/dist/server.cjs
```

以上是两个服务各自的启动命令，按需单独运行。手动配置 stdio 客户端时，将对应入口解析为本地实际路径后填入参数。
独立 stdio 调试没有加载原生扩展的额外文件接口；完整接入与验证要求见[开发指南](../development/README.md)。
