# Univer 扩展

Univer 是独立的 OpenClaw 离线表格扩展，附带 MCP App。扩展标识为 `univer-app`，MCP 服务名为 `univer`，当前版本为 0.1.0。

使用 [Univer](https://github.com/dream-num/univer) 1.1.0 开源 Sheets Core，不包含商业 Pro 功能、授权服务器或默认公网服务。
XLSX 转换由随包提供的 ExcelJS 4.4.0 完成，不连接在线转换服务。

## 安装与打开

安装 Univer 的完整交付目录或对应 `.tgz` 文件，完成扩展审查并启用。仓库生成的独立导入目录为 `dist/plugins/extensions/univer/`，压缩包位于 `dist/archives/extensions/`。
包内包含原生清单、扩展入口、说明和完整 `dist/`，运行使用宿主的 Node 24，无需安装 npm 依赖或联网。
`edit_spreadsheet`、`update_cells`、`read_range`、`inspect_spreadsheet` 及界面操作预检使用随包提供的独立无界面引擎 Worker；单次执行限时 15 秒，运行中及排队请求合计最多 16 个，取消或关闭服务会清理对应资源。

启用后附带的 MCP 服务由 OpenClaw 管理，可通过手动应用入口或模型工具打开。
本地文档库支持新建、导入和重新打开表格。
停用或卸载父扩展会撤下 MCP 服务和应用入口，已保存的用户文档保留。
服务和工具提供随包的明暗 SVG 图标；原生 `skills/spreadsheet-workbooks/` 帮助模型按需发现表格任务与实际工具，随扩展启停，不改变宿主工具授权。

## 基本使用

1. 从本地文档库新建表格、导入文件，或让模型使用创建工具打开表格。
2. 在编辑器中修改单元格、公式和格式；普通文档点击“保存”持久化到本地文档库。
3. 选择导出格式并点击下载按钮将内容另存为文件；直接打开工作区文件时，“保存”用于写回该源文件。

示例：“用 Univer 建一个项目预算表，列为项目、预算、实际支出，填入以下数据……”
模型应使用真实用户数据。用户选区会以有界上下文反馈给当前模型，普通编辑仍需主动保存。

支持可选展示扩展 `ui/shared-header` v1：与支持该能力的宿主协商后，共用单行标题区域，表格保留完整宽度，保存与导出仍在插件内执行。普通本地文档可通过重命名按钮修改标题，再主动保存；工作区源文件不通过该按钮改名。宿主不支持、未提供或撤回布局时，恢复完整的独立标题栏，当前编辑器与未保存内容保留。

## 格式与能力

| 项目       | 支持范围                                                  |
| ---------- | --------------------------------------------------------- |
| 导入       | XLSX、CSV、TSV、工作簿 JSON                               |
| 导出       | 多工作表 XLSX、当前工作表 CSV/TSV、完整工作簿 JSON |
| 单元格     | 文本、数值、布尔值、公式和已有缓存结果                    |
| 基础格式   | 常见字体、颜色、数字/日期格式、合并、行高列宽、冻结与隐藏 |
| 本地交互   | 排序、筛选、查找替换、数据验证与条件格式 |
| 本地文档   | 创建、列表、重新打开、版本检查和保存                      |
| 工作区文件 | XLSX、CSV、TSV 文件预览，受限授权下的源文件写回           |

CSV 导入将以 `=` 开头的文本保持为文本。模型写公式必须显式提供 `formula` 字段，例如 `update_cells` 中的单元格更新。
预览保留 Excel 已有缓存结果，编辑后仅由 Univer 支持的函数重新计算。

离线配置通过公开函数注册关闭会主动加载外部图片的 `IMAGE()`；重新计算时返回 `#NAME?`。导入时保留其它已有公式缓存，不为展示图片发起网络请求。远程转换、协作服务及商业 Pro 能力不在本扩展范围内。

排序、筛选、查找替换、数据验证和条件格式使用与核心匹配的开源官方插件，代码、样式和中英文资源随包交付；不连接公共数据服务。数据验证与条件格式可以通过原生界面配置，本地文档及完整工作簿 JSON 保留其规则。

当前 XLSX 转换器不能完整表达这些插件的筛选、验证及条件格式资源；存在有效规则时会阻止 XLSX 导出并提示使用完整工作簿 JSON，避免无提示丢失。清空规则后恢复普通 XLSX 导出。CSV/TSV 导出当前工作表的值及已计算结果，不包含样式或规则；完整 JSON 可重新导入并继续编辑。

## MCP 工具

| 工具                               | 用途与调用约定                                                                             |
| ---------------------------------- | ------------------------------------------------------------------------------------------ |
| `create_spreadsheet`               | 从列标题和行数据创建可编辑表格                                                             |
| `update_cells`                     | 更新已有表格；先读取文档，提供当前 `expectedRevision` 和准确的 `sheetId`，行列索引从零开始 |
| `edit_spreadsheet`                 | 按 revision 执行一次样式、区域、工作表或行列操作；通过同版本真实引擎处理公式引用 |
| `inspect_spreadsheet`              | 检查支持的操作、工作表、范围值和样式、合并/冻结/隐藏及插件资源摘要 |
| `read_range`                       | 读取已保存工作簿的指定范围，默认 20×10、最大 100×20；返回值、公式及当前 revision           |
| `list_documents`                   | 列出当前本地文档                                                                           |
| `open_document`                    | 按文档 ID 打开已保存文档                                                                   |
| `read_document`                    | 读取最新数据和版本，模型修改前应先调用                                                     |
| `open_editor`                      | 打开手动入口与本地文档库                                                                   |
| `new_document`                     | 新建空白文档                                                                               |
| `import_document`、`save_document` | App-only 文档导入与保存接口                                                                |
| `preview_file`                     | App-only 工作区文件入口，声明 `.xlsx`、`.csv`、`.tsv`                                      |

更新单元格时每项只能提供 `value` 或 `formula` 之一；公式必须以 `=` 开头。
多个窗口或模型写入同一文档时，旧版本保存会被拒绝，不能覆盖较新数据。
遇到冲突应先保留或导出当前修改，再重新读取；不自动合并或后台自动保存。
`read_range` 的完整结构化结果最多 256 KiB（UTF-8）；长文本超出时缩小行列范围。

## 当前编辑器接口与对话准备

以下是浏览器 App 的工具，通过宿主已经准入的确切 `AppBridge.listTools` / `AppBridge.callTool` 调用；stdio 工具目录只操作已保存数据，两者分开。内容戳和文档 ID 用于业务冲突检查，不替代当前会话与视图权限。

| App 工具               | 用途                                                                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `prepare_context`      | 无参数；提交正在输入的单元格、等待公式结果，并等待 `updateModelContext` 成功；以 `workspace/prepare-context: true` 标记供支持约定的宿主发现 |
| `spreadsheet_snapshot` | 无参数；读取当前 `documentId`、标题、revision、未保存状态、`contentStamp`、工作表列表及有界选区/预览                                        |
| `spreadsheet_query`    | 读取当前值与公式；参数 `sheetId`、`startRow`、`startColumn`、`rowCount`、`columnCount`，默认 20×10，最大 100×20                             |
| `spreadsheet_inspect`  | `kind: capabilities/range/sheets/resources`；发现操作规范，读取当前未保存内容及样式、布局和资源摘要 |
| `spreadsheet_apply`    | 按内容戳在同一实例执行一次操作；兼容原有单元格批量更新，保持原生撤销，不自动保存 |

apply 参数为 `operationId`（本次唯一，1–128 字符）、`documentId`、`baseContentStamp` 及 `patch`。例如：

```json
{
  "operationId": "edit-budget-unique-id",
  "documentId": "snapshot 返回的文档 ID",
  "baseContentStamp": "snapshot 返回的 UUID",
  "patch": {
    "sheetId": "sheet1",
    "cells": [
      { "row": 1, "column": 1, "value": 120 },
      { "row": 2, "column": 1, "formula": "=B2*2" }
    ]
  }
}
```

每批最多 1000 个不重复单元格，只能修改现有工作表范围。`value` 中的字符串保持文本；单元格不能同时提供 `value` 和 `formula`。其它单元格与样式保留，编辑器和撤销栈继续复用。只读文件拒绝 apply；需先保存副本才能编辑。

也可以使用 `patch: { "operation": { … } }`，与旧的 `sheetId/cells` 写法二选一，每次提交一种操作：

| 操作 | 用途 |
| ---- | ---- |
| `cells`、`format_range` | 批量修改单元格，或对区域设置字体、颜色、边框、数字格式、对齐与换行 |
| `clear_range` | 清除内容、格式或两者；其它模式保留对应内容 |
| `merge`、`unmerge` | 合并或取消合并；默认拒绝丢弃非左上角已有数据 |
| `add_sheet`、`rename_sheet`、`delete_sheet`、`copy_sheet`、`move_sheet`、`set_sheet_hidden` | 管理工作表，保留至少一张可见表；复制使用上游生成的新名称和 ID，从新快照取得 |
| `insert_rows`、`delete_rows`、`insert_columns`、`delete_columns` | 插删行列，由原生公式引擎维护引用 |
| `resize_rows`、`resize_columns`、`set_rows_hidden`、`set_columns_hidden` | 调整行高列宽及隐藏状态 |
| `freeze`、`sort_range`、`set_filter` | 冻结行列、排序及设置/清除筛选范围 |

区域采用从零开始、包含两端的 `startRow/endRow/startColumn/endColumn`；每次最多 10000 个区域单元格。名称、边界、合并冲突、容量和特殊公式会在修改前检查。存在未知非空插件资源时拒绝结构操作，避免错误移动无法解释的资源。排序沿用上游对隐藏、过滤行的行为。共享公式在读取、保存与导出副本中通过公开公式接口展开，实时模型和撤销栈保持不变。

`rowData` / `columnData` 的索引也必须位于声明的行列范围内；显式声明 5001 行的旧版带表头工作簿继续兼容。XLSX 导入将空白隐藏行及只有宽度/隐藏属性的列计入容量，导出和重新导入保留这些属性，不添加文本内容。

样式示例：

```json
{
  "operation": {
    "type": "format_range", "sheetId": "sheet1",
    "range": { "startRow": 1, "endRow": 10, "startColumn": 2, "endColumn": 2 },
    "style": { "bl": 1, "bg": { "rgb": "#E8F0FE" }, "n": { "pattern": "#,##0.00" } }
  }
}
```

先调用 `spreadsheet_inspect(kind: capabilities)` 发现实际 schema，再读取新内容戳执行。保存数据工具与实时界面复用相同操作和引擎规则；实时操作的预检是无持久化的只读调用，不重新运行创建或保存工具。成功后仍须主动保存。

成功结果为 `{ "operationId": "…", "status": "applied", "snapshot": { … } }`，说明当前界面已应用，仍须主动保存。错误目标、手改、过期戳、重复操作及已关闭实例返回 `isError: true`，未知结果不自动重放。每个编辑器保留最近 8 个内容戳和最多 128 个操作 ID；重新打开文档后使用新戳。

快照预览与对话上下文最多 16000 UTF-8 字节，长字符串最多 240 字符；必要时返回 `previewOmitted: true`，精确值通过 query 获取。单次 query 结果最多 256 KiB，超出时缩小窗口。文件只同步名称、数据与只读状态，资源令牌和 ETag 不进入上下文。发送前准备失败时不能宣称已同步，也不会保存或发送消息。
当前工具在提交输入前暂时锁定编辑区，并在计算、校验、应用或上下文同步完成后恢复，防止等待期间的新单元格输入被覆盖。切换文档也保持该保护，旧编辑器在新内容加载成功前保留。

## 工作区文件预览与源文件保存

`preview_file` 声明 `.xlsx`、`.csv`、`.tsv` 文件入口，接收原生授权的文件资源并显示表格内容。
插件校验文件类型、大小、工作区归属与授权有效性，不接受任意本机路径。

### 写回与冲突

打开授权文件后可直接编辑，点击“保存”或 Ctrl+S 写回当前源文件；“导出 XLSX”仍可另存文件。
保存前核对读取时的 SHA-256 ETag，原文件被其他程序修改时拒绝覆盖并保留当前编辑。
“重新读取”读取最新源文件，未保存修改需确认放弃。缺少有效写入能力或授权时，只提供只读预览。
“保存副本”将当前内容保存为新的本地文档库文档；它不覆盖源文件，适合只读预览后继续编辑。
保存等待期间可以继续编辑；响应返回后提交仍在输入的单元格并核对当前内容。新编辑保持未保存状态；若保存副本时新增了编辑，保留当前工作簿并提示，不切换到较旧副本。
原件在原生状态目录 `plugin-data/univer/backups/<uuid>/<原文件名>` 及配套 JSON 中备份，
备份失败则不写源文件，源文件使用公开 SDK 的安全原子替换；替换前再次核对 ETag。
权限、插件准入、工作区归属与生命周期改变后拒绝保存。
保存结果未知时不重复写入，须核对源文件后重新打开。

XLSX 源文件保存支持单元格内容、公式和基础格式；在原 OOXML 包中更新对应单元格和追加格式，
保留未修改的图片、图表、富文本、关系及其它未知部件，不用完整转换结果覆盖原包。
基础样式按实际改动合并，保留未修改的主题字体、斜线边框和对齐附加属性。
插入/删除/重排/重命名工作表、行列及布局改动暂不支持保存回源文件，会明确报错并保留编辑。
受保护工作表和带数字签名的工作簿不支持在此写回。CSV/TSV 以原扩展名、分隔符、BOM 和换行格式保存。

1904 日期系统在源文件写回时保留原日期基准；日期和常规数字格式之间切换时，保存后的值与编辑器显示保持一致。
共享公式、数组公式和数据表公式的公式本身改动暂不支持写回。

新增或改变筛选、数据验证、条件格式规则也不写回源 XLSX；会在文件提交前拒绝，当前编辑仍保留，可保存本地副本或完整工作簿 JSON。规则添加后全部删除视为恢复无规则状态，不阻止原有单元格写回路径。

### 原生文件接口与授权

工作区文件快照沿已有原生 MCP 连接以 `app-file://` 资源提供；应用只接受不透明资源标识，不接受本机路径。
普通 `openclaw-file://` 文件入口保留兼容。首次读取的是只读快照，保存源文件需要单独核对写权限和审批。

大文件接口属于 Univer 扩展：`mcp-app-files.open.<serverName>` 接收文件打开请求和当前
sessionKey/sessionId/agentId。
扩展用公开 SDK 检查原生会话身份、生命周期与当前工作区，并拒绝远程工作区、符号链接、
硬链接和同名 MCP 覆盖。文件快照沿现有原生 App view、App-only 工具与 `resources/read` 传递，
不建立第二套 MCP 连接，不拓展宿主文件读取权限，也不修改 OpenClaw 补丁。
首次快照仅在 MCP 进程内存中短存（10 分钟、最多 4 份且共 32 MiB）；文件原生授权同样有界，
通过 `mcp-app-files.resource.univer` 在当前视图内读最新源文件和提交保存，到期需重新取得文件授权。
写回先调用 App-only `authorize_workspace_file_save`，由原生 MCP 权限/审批核对准确保存意图，
再由扩展按已保存的精确文件路径、当前原生身份和 ETag 提交一次，不接受 UI 传入文件路径。
不透明令牌不进入模型上下文，选区仅反馈文件名和有界数据。

编辑器偏好设置通过公开服务使用每视图内存，避免依赖 opaque frame 中不可用的 IndexedDB 或 localStorage。

## 容量限制

| 项目                               | 上限                            |
| ---------------------------------- | ------------------------------- |
| 原生扩展直接打开或主动导入的源文件 | 10 MiB                          |
| XLSX 解压后总大小                  | 64 MiB                          |
| 转换后的工作簿或持久化文档         | 8 MiB                           |
| 每个工作簿                         | 20 个工作表                     |
| 每个工作表的数据                   | 5000 行、100 列                 |
| 临时工作区文件快照                 | 10 分钟，最多 4 份，总计 32 MiB |

独立 stdio 调试未加载扩展的文件接口时，普通原生文件通道仍受 256 KiB 限制。
工作区以外的文件通过应用内的“导入表格”主动选择。

## 本地数据与备份

普通文档保存在用户目录下的 `.local-mcp-apps/univer/documents.sqlite`，可通过 `MCP_APP_DATA_DIR` 指定数据目录。
文档库是跨会话的本地集合，不保存聊天、模型凭据或原生执行状态。
不同窗口的修改需重新读取后显示；重启服务后可继续打开已经保存的文档。
重复的同版本工具结果保持当前实例；新的内容加载失败会保留原编辑器。恢复范围为已保存文档，已销毁实例的未保存草稿和撤销栈不持久化，也不提供原生聊天历史回执恢复。

工作区源文件保存与普通文档库保存是两条不同的操作路径；源文件的备份位置、授权和冲突处理见上文。
备份文档库时先停用服务，再复制整个数据目录，包括 SQLite WAL；卸载扩展不自动删除用户文档。

## 兼容范围

编辑器显示与普通导出不承诺保留图片、复杂图表、条件格式、透视对象或完整富文本，也不支持全部 Excel 函数。
源文件写回会保留未修改的原始部件，但这不意味着整个编辑器具备无损 Excel 往返能力。
`.xls` 和 `.xlsm` 不支持；没有 PDF 交换、多人协作、大数据后端或云端分享。
